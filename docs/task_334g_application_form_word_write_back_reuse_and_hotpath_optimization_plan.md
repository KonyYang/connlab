# TASK_334G Application Form Word Write-Back Reuse And Hotpath Optimization Plan

## 1. Objective

Optimize the real Project Folder `Updating Application Form` step, now measured at about `8.8s` in the Workbench flow, by first proving where the real-path time is spent and then adding a safe fast path for unchanged Application Form outputs.

This task is intentionally narrower than a general Word COM rewrite. The expected high-value optimization is avoiding Word COM entirely when ConnLab can prove that a previous filled Application Form is still valid for the current selected source form and confirmed Basic Information.

## 2. Current Phase / Active Task / Allowance

- Current phase: `Phase 11 - Project Workbench / Matrix / Approval Package controlled foundation`
- Current active task on board: `TASK_334F_LTR_WORKBOOK_READONLY_OPEN_AT_EXACT_DL_MATCH` is complete.
- Why this task is allowed now: the user explicitly requested a new optimization pass for Application Form Word write-back after real smoke showed it is the current largest remaining bottleneck.
- Current status: plan only. Implementation must wait for explicit user approval.

## 3. Current Behavior From Code Reading

Relevant files:

- `backend/application/project_application_form_write_back_service.py`
- `backend/infrastructure/office/application_form_word_gateway.py`
- `backend/infrastructure/office/office_facade.py`
- `backend/application/project_output_record_service.py`
- `backend/application/official_project_workspace_service.py`
- `frontend/src/features/project-workbench/useProjectWorkbenchModel.ts`

Observed flow:

1. Workbench creates or rebuilds the official workspace.
2. It archives request materials into `Submitted Material`.
3. It generates Required Forms.
4. It calls Application Form write-back as a separate post-folder step.
5. `ProjectApplicationFormWriteBackService.write_back(...)`:
   - resolves the selected copied `.docx`
   - validates confirmed Basic Information
   - checks managed-target safety
   - always calls `write_word_application_form_fields_with_owned_session(...)`
   - registers a `SECTION2_WRITE_BACK` output record

Existing safety check:

- Blocks if a previously managed target was manually edited.
- Allows a rebuilt target restored to the original source hash.

Missing performance fast path:

- If the same source Application Form and same Basic Information have already produced a verified filled `.docx`, the service still opens Word and writes again.
- Existing output records do not include an Application Form write-back mapping token, so the system cannot distinguish `.docx` files generated by old field/header rules from files generated by the current rules.

Important rebuild constraint:

- In `Backup and Rebuild`, `official_project_workspace_service.py` can move the old official folder before Application Form write-back runs.
- A later reusable-artifact lookup that only reads the previous output record path may fail because the file was moved into a backup folder or deleted in overwrite flow.
- Therefore TASK_334G must either:
  - capture a reusable artifact before folder replacement, or
  - explicitly document that reuse only applies to non-rebuild/update cases.

The preferred implementation is to support real rebuild reuse if it can be done with a narrow, safe pre-rebuild artifact-capture seam.

## 4. Design

### 4.1 Add Service Timing DTOs

Add an application-level timing DTO, for example:

```python
@dataclass(frozen=True, slots=True)
class ApplicationFormWriteBackTiming:
    label: str
    elapsed_ms: int
```

Extend `ProjectApplicationFormWriteBackResult` with:

```python
timings: tuple[ApplicationFormWriteBackTiming, ...] = tuple()
office_timings: tuple[ApplicationFormWriteBackTiming, ...] = tuple()
```

The API response may expose these as optional structured lists. This is backend observability, not a frontend UI change.

Required service labels:

- `application_form.resolve_inputs`
- `application_form.resolve_target`
- `application_form.basic_information`
- `application_form.safety_check`
- `application_form.reuse_lookup`
- `application_form.reuse_copy`
- `application_form.office_write`
- `application_form.register_output`
- `application_form.total`

If the Office writer returns `OfficeTimingSnapshot`, convert its stages into `office_timings`.

### 4.2 Strengthen Context Signature

Current signature:

```text
application-form:{form_id}|{basic_information.context_signature}
```

New signature:

```text
application-form:{form_id}@source:{source_hash_or_unknown}|{basic_information.context_signature}|application-form-output:lab_section_v1
```

Rules:

- If selected source hash is known, include it.
- If source hash is unknown, include `source:unknown` and do not reuse across unknown-source outputs unless target path and managed fingerprint still prove safety.
- `application-form-output:lab_section_v1` is the explicit write-back mapping token for the current TASK_332C field scope and header-layout behavior.
- Any future change to Application Form write-back fields, critical-field semantics, or header normalization must introduce a new token before reuse is allowed.
- Existing old-format records are not reusable for the new fast path. They can still protect against manual edits.

### 4.3 Add Reusable Application Form Artifact Port

Add a protocol beside the service:

```python
class ReusableApplicationFormArtifactReader(Protocol):
    def find_current_artifact(
        self,
        *,
        project_id: str,
        source_context_signature: str,
        final_target_path: Path,
    ) -> Path | None:
        ...
```

Default implementation:

```python
class NullReusableApplicationFormArtifactReader:
    ...
```

Infrastructure/API dependency implementation should use `ProjectOutputRecordService.get_status_summary(...)`.

Reuse checks:

- output kind is `SECTION2_WRITE_BACK`
- status is `CURRENT`
- source is `SYSTEM_GENERATED`
- source context matches exactly
- output path exists
- output path is not the final target unless it is already the current managed target
- output suffix is `.docx`
- output hash exists and matches the current file

If the current target is already the same managed output and context matches, the service should return `status="current"` without Office write.

### 4.4 Handle Backup/Rebuild Real Path

Because the old official folder may move before Application Form write-back starts, TASK_334G must validate this with real timing.

Implementation options, in preferred order:

1. **No structural change if existing artifact remains accessible.**
   - If backup strategy moves old folder to a sibling backup path but output record path can be resolved or updated before write-back, reuse from that path.
   - This is unlikely with current output records because they store the old final target path.

2. **Pre-rebuild artifact capture seam.**
   - Before official workspace conflict resolution moves/deletes the old folder, capture only the verified current Application Form output into a ConnLab temp/staging path.
   - Capture only when source context matches the current planned signature and output hash validates.
   - Pass the staged artifact to the later Application Form write-back step through an explicit application-layer operation context.
   - Clean up ConnLab-owned temp artifacts after successful placement or retain only under an operation diagnostics folder on failure.

   Required data flow:

   1. Workbench/Project Folder orchestration computes the planned Application Form context before calling Official Workspace create.
   2. A narrow capture service inspects the latest `SECTION2_WRITE_BACK` output record.
   3. If the record is `CURRENT`, `SYSTEM_GENERATED`, context-matching, `.docx`, and fingerprint-valid, it copies that file to a ConnLab-owned operation temp path, for example:

      ```text
      {workspace root}/.connlab/tmp/application-form-reuse-{operation_id}/application-form.docx
      ```

   4. Official Workspace create may then move/delete the old folder.
   5. `ProjectApplicationFormWriteBackService.write_back(...)` receives the captured artifact path as an optional operation input.
   6. The service verifies the captured artifact hash again before copying it to the new target.
   7. On success, the operation temp directory is deleted after output registration.
   8. On failure after capture, the temp directory is retained only under a diagnostic operation folder and is never registered as the official output.

3. **Fallback-only.**
   - If pre-rebuild capture would require broad Official Workspace orchestration changes, do not implement it in TASK_334G.
   - Document that reuse only applies to non-rebuild update.
   - Still add timing visibility and service-level same-target current skip.

The plan allows option 2 only if the implementation can be kept narrowly scoped and covered by tests. It must not redesign the Project Folder conflict workflow.

### 4.5 Write-Back Decision Flow

Inside `ProjectApplicationFormWriteBackService.write_back(project_id)`:

1. Resolve project/workspace/form/target/source hash.
2. Load confirmed Basic Information.
3. Build fields and new context signature.
4. Run existing safe-managed-target check.
5. Try current-target skip:
   - if latest managed output points to this target
   - context matches
   - fingerprint matches
   - return `current`
6. Try reusable artifact:
   - if reader returns a verified filled docx or the operation context supplies a captured verified filled docx
   - copy it to target through a safe gateway or `shutil.copy2`
   - register output with the same context signature
   - return `reused`
7. Fall back to `write_word_application_form_fields_with_owned_session(...)`.
8. Register output record.

### 4.6 Output Record Status

For context-bound Application Form write-back, register:

```python
status = ProjectOutputStatus.CURRENT
source = ProjectOutputSource.SYSTEM_GENERATED
source_context_signature = new_context
```

Do not downgrade to `MANUAL` just because there is no active Matrix draft. This mirrors the Required Forms follow-up rule: a system output with a source context can be current even without an active draft.

### 4.7 Safety And Recovery

- Never reuse a docx whose hash does not match its managed output record.
- Never overwrite a target that differs from the stored managed hash unless it is exactly the restored source copy and source hash is known.
- If reusable copy fails, return a business error or fall back only when no target has been mutated.
- If Word COM fallback runs, keep existing `OpenAndRepair=False` validation smoke.
- Do not kill user-owned Word processes.

## 7. Risks

- **Backup/Rebuild artifact loss:** Old managed output may move before write-back starts. This is the main risk to the reuse optimization.
- **False reuse:** Reusing without selected source hash could copy stale data into a new project folder. This is why source hash must be part of the new context when available.
- **Stale mapping reuse:** Reusing without a write-back mapping token could preserve old Application Form header/field behavior after rules change. This is why the context must include `application-form-output:lab_section_v1`.
- **Output-record compatibility:** Old records have old context signatures. They should protect manual edits but should not be considered reusable under the new strict reuse path.
- **Broader orchestration creep:** If real rebuild reuse requires broad changes to Official Workspace conflict handling, stop and document instead of redesigning the flow in this task.
- **COM variance:** When reuse is unavailable, Word COM timing may still vary. The task should expose timing rather than hiding variance.
