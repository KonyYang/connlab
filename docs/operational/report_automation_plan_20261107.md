## 1. 结论

ConnLab 已经有报告自动化所需的大部分基础能力，**不需要推倒重写，也不应该再开发一套报告平台**。当前最主要的问题是：现有能力没有接成用户可以连续完成工作的路径。

目前可以初始化报告、导入现成底稿、保留来源和确认映射、处理部分测试结果、替换照片槽位、生成和检查客户副本。但这些操作分散在两条报告链及独立 Tools 工具中，仍要求用户重复选择文件、列、样品、报告目标和图片。

建议的目标不是“选一个目录，无人审核就正式发行”，而是：

> 选择资料范围和底稿 → 软件整理并匹配证据 → 集中处理少数真实疑点 → 一次生成完整审阅稿 → 核对页面并生成客户版 → 用户明确决定交付。

优先顺序：**统一工作版本 → 接通 Tools 整理成果 → 补齐证据与结果类型 → 批量装配和照片匹配 → 完成交付检查与受控保存**。不把已经完成的温升、机械 Summary、局部更新保真和客户包检查重新做一遍。

## 2. 参考任务真正要求软件完成什么

[参考对话](codex://threads/01a173db-15c6-7dd2-9f4c-481fee2b1823)不是简单把 Excel 数字复制进 Word。它包含以下工作：

1. 识别本项目资料与历史参考资料，区分当前项目、版式参考和获准沿用的外部结果。
2. 从申请、规格、Matrix、原始记录、Summary、照片和邮件中确定真实的组别、步骤、样品与接受要求。
3. 利用 021 的批准稿版式生成 032 报告，但不能继承 021 的项目身份、规格、数值、照片和 Pass。
4. 把 LLCR、力学、电气、温升和定性结果映射到正确的正文与附录。
5. 按本项目确认使用 032B 温升结果、EK550 相关结果，并保留适用性依据。
6. 对特殊接受理由、定性结果和设备沿用作项目级确认，不能推广成其他项目默认值。
7. 保持批准稿结构、图片槽位和人工排版，完成内部版和客户版的差异化交付。

## 4. 架构上的主要问题

### 4.1 两条报告链并存，缺少统一工作对象

现有主报告链处理初始化、LLCR、设备表、当前报告和正式保存；`report_authoring` 处理来源、温升/CR/机械、图片和客户审核副本。后者明确不发布，生成时使用 `make_current=False`。

这种隔离保护了真实文件，但也使“刚完善的副本”和旧按钮作用的“当前报告”不是同一个对象。不能通过把所有调用改成 `make_current=True` 来解决，否则会把逐项编辑变成未经明确确认的现行文件替换。

建议统一**当前选定的工作版本**，同时保留**正式现行版本**作为独立状态。所有内容更新明确指向工作版本；只有最后的受控保存才进入现有发布链。

### 4.2 结果整理和报告填充之间缺少共享交接契约

温升和机械 Tools 已经完成了大量确认，但 Report 仍要求重新选择 sheet、列、行、样品和类型。

不仅耗时，也有二次解释风险：

- 温升 Tools 允许使用确认后的有效系数；Report 当前重新 analyze，不能默默覆盖用户采用的系数。
- 机械 Tools 可以保留原始负拔出力并按确认口径展示幅值；Report 当前机械 reader 拒负值，不能直接把两条路径等同。
- Tools 已有定性矩阵，而 Report 的机械导入只支持 mating/unmating/retention。

解决办法是共享一个小型、版本化的结果交接契约，不是让 Word writer 反过来猜每份 XLSX 的布局。

### 4.3 通用字典和自由文本不足以承担更多结果类型

现有来源和映射结构是良好起点，但结果仍主要存为字典，多个类别共用一个有许多无关字段的请求。继续加入 IR/DWV、外观、委外引用时，应在实际新增类型处引入明确的判别类型及验证规则。

保留现有 JSON revision 存储，增加可识别的 schema version 和兼容读取即可。**不要把异构结果直接塞入仅支持 LLCR 的旧 ResultDataset，也不必先改造整个数据库。**

### 4.4 逐条 Word 操作没有全报告覆盖证明

当前一次 result 更新通常生成一个副本。用户需手选 Word 结果行、附录及证据 block 范围。精确哈希有保护，但不能替代“全报告每个必要项目都已覆盖”的验证。

建议把低层定位留作异常修复界面，由后端生成一个包含所有已选变更的报告更新计划。正文结果、附录、图片和客户版都消费同一份确认结果。

### 4.5 跨项目版式参考还不是自动安全模板

现有 reference 准备会替换 DL、清空 Result/Comment，但 Purpose、Conclusions、样品、规格、附录与照片仍需要处理。当前依靠提示和内容审核，不能自动证明旧事实已全部替换。

需要将“可复用版式/固定句式”和“必须替换的项目事实/结果”分开。不能用全局查找替换代替规格、日期、接受理由和图表语义核对。

## 5. 推荐的用户流程

保留 Report Workspace，在其中形成一个主工作区，不为每种 Summary 再增加一个独立的主按钮。

### 使用前提：资料目录不是已确认的测试范围

当前报告结果确认依赖项目身份和已确认 Matrix；参考对话则是从一个资料文件夹开始。首版应明确区分：

- 已有项目与确认 Matrix：直接进入下述报告准备流程。
- 只有历史目录或普通文件导入：先复用项目导入/关联能力；允许盘点资料、保留候选和识别测试范围，但在结果正式绑定前，通过现有 Matrix 流程确认实际范围。
- 可以从已有申请、规格和测试记录辅助预填候选，不要求无意义地重录资料；但“目录收到”“检测到 LTR”“发现旧测试状态表”都不能自动生成已确认 Matrix 或通过结论。
- 独立机械/温升 Tools 继续无需项目。若未来还要求“完全不关联项目或 Matrix，单凭任意目录就生成整套报告”，应单独确定其范围权威与交付规则，不把这一变化藏在目录扫描中。

因此，032 的端到端验收包含建立/关联隔离项目和核对其测试范围，不能只测选目录后下载一个 Word。

### 第一步：选择底稿和资料

- 默认显示项目关联的受控文件夹，执行只读盘点。
- 用户选择继续本项目原稿、使用批准版式参考，或从标准模板新建初稿。
- 已有当前工作版本时优先继续，不因点了“生成”而回到空白模板。
- 可补充关联报告、规格、邮件及独立资料；这些是补充来源，不改变项目身份。
- `History`、临时文件、旧输出和其他项目默认不作为当前测量证据；必要引用通过显式选择加入。

### 第二步：集中处理疑点

按 Group/Step 显示一张清单：已就绪、需确认、缺资料、不适用。正常项折叠，只突出疑点。

例如：

| 项目 | 软件已找到 | 需要用户处理 |
|---|---|---|
| Ab 插拔力 | 已确认的六条记录、颜色和统计 | 若无变更，不再询问 |
| Ad LLCR | Summary 与原始标签冲突 | 选择正确阶段，显示双方依据 |
| Group C 温升 | 032B 关联报告 | 确认本项目适用性及采用范围 |
| MFG | 委外观察与接受要求 | 确认本项目接受理由 |
| 试后照片 | 多张候选图 | 只核对冲突和缺失槽位 |

“资料不齐”“数据不合格”“尚未确认”“程序执行失败”必须区别展示，不能都写成生成失败。

### 第三步：一次生成审阅稿

显示本次会更新哪些事实、结果、附录和照片，哪些不会更新。用户一次确认后，后台连续执行，不在每个 Summary、每张照片之间重复询问。

有未决项时可以继续准备独立部分，但只能形成不完整审阅稿，不能显示全部完成。未确认的历史 Pass 不进入当前项目结论；不能把内部 `Pending/Review` 状态塞进正式结果栏。

### 第四步：审阅与交付

- 同时显示内部审阅稿、客户审阅稿各自来源和版本。
- 先完成数值、覆盖、引用、保密检查，再查看 Word 真实渲染。
- 只重新检查发生变化的内容及受影响页面；最终交付仍检查整份文档完整性。
- “文件已生成”“内容检查通过”“人工验收”“已保存为现行报告”“正式发行”不是同一个状态。
- 正式保存/发行保留明确动作，不因自动生成而隐含授权。

## 6. 最小合理技术设计

```text
项目资料库 / 补充上传 / 已确认的 Tools 整理成果
                     ↓
              来源与候选证据盘点
                     ↓
    现有 report_authoring 来源、映射、结果 revision
                     ↓
      报告更新计划：目标、依据、差异、未决项
                     ↓
   现有局部 Word 写入器，在一份隔离副本上串行装配
                     ↓
          内部审阅稿 → 客户副本与交付检查
                     ↓
       用户明确采用 → 现有版本/History/发布保护
```

### 6.1 只建立三个必要边界

1. **结果交接契约**：表达已整理的测量、统计和确认，不包含 Word 坐标。
2. **报告更新计划**：把结果和事实绑定到选定报告的可验证区域，集中处理冲突与依赖。
3. **文件适配器**：现有 Excel、PDF、Word、图片实现，只负责读取或受控写入。

建议对 `report_authoring` 增加 `prepare_update_plan` / `apply_update_plan` 这类业务接口。名称为设计建议，实施时结合实际模块收口；不要求机械创建一层层同名 wrapper。

不新增通用工作流引擎、微服务、向量数据库、平行任务调度平台或第二套正式发布机制。

### 6.2 已整理结果包

“结果包”是逻辑契约，不强制用户管理一个新文件夹或多个 JSON。最小内容如下：

| 信息 | 必要含义 |
|---|---|
| 契约版本、结果类型 | 能明确识别温升、CR、LLCR、力学、电气、定性或引用结果 |
| 来源 | 文件身份、原始 SHA、sheet/单元格或页/区域、原始值与公式状态 |
| 对象 | Group/Step、样品 SN、颜色/部位、测点、仪器记录 ID；不合并成一个字符串 |
| 测量语义 | 阶段、绝对量/增量、峰值/保持、实测/回归、单位、保持时间 |
| 计算 | 精度、统计总体、标准差定义、算法/解析器版本、有效系数及采用理由 |
| 判断 | 采用的要求与来源、计算建议、人工最终决定和例外理由；三者分开 |
| 证据资产 | 原始曲线、照片、关联报告等引用，不把图片全部当成正式插图 |
| 依赖与确认 | 源版本、确认的范围、人员/时间；源变化能判断哪些结果需重新核对 |

存储建议：扩展现有 report authoring revision 与资产仓库。LLCR 通过已有 dataset 的只读投影接入，保留原记录；不要大规模迁移已确认数据。

Tools 继续项目无关。通过 Report 发起时可以把结果直接交回当前项目；从独立 Tools 导出的 XLSX 可附带轻量版本化元数据，方便日后采用。元数据只是解析线索，不能当作可信签名：

- 元数据必须绑定实际结果区域和源证据；人工改了数值、公式或映射，需要重新校验相关部分。
- 工作簿整体 SHA 在导入后由服务器记录，不在文件内部形成自引用哈希。
- 普通人工 Summary 没有元数据时仍可用，走首次列/区域确认。
- 不复制浏览器 localStorage 中的“已确认”就当作服务器批准；先核对实际源字节与确认范围。
- 用户始终能拿 XLSX 审阅、打印和人工更新，不能为了软件契约剥夺这一用途。

### 6.3 来源盘点及依赖失效

复用项目库的目录身份、安全路径检查与资产携带，不以 LTR 相同或文件名相似就确认归属。

普通盘点只读目录，不操作公盘文件。首次采用证据时保留必要副本和指纹；再次打开先做轻量候选检测，实际使用或发布前核验准确字节。不能只凭修改时间判定数据有效，也不要每次打开页面重算整个项目树。

依赖失效按实际消费内容判断：换一张照片不重算所有力学；修改一个机械源不撤销无关温升确认。Matrix 版本改变时必须检查所绑定步骤；只有能够证明映射和要求没有变化才复用，不能仅为少提示而放宽检查。

已批准的历史结果是一个固定来源版本。文件夹里出现同名新稿时提示选择，不能自动以最新修改日期替代已批准版本。

### 6.4 报告目标定位

现有数字 table/row/block 定位作为首次人工配置和兼容后备，不作为长期保存的唯一身份。

优先使用 Group/Step、表头结构、字段语义与区域指纹定位；新增受控输出可使用已有风格的 content-control 标记。对旧模板不强制批量改原件；在副本中建立映射即可。

同一计划内若多个更新命中相同单元格、附录或图片，必须在写文件前解决冲突。不能先写第一项导致表索引变化，再把后续项写错位置。

### 6.5 批量执行、恢复和失败处理

复用现有暂存、版本、锁和诊断机制，增加一条轻量的报告装配操作记录即可：源版本、计划摘要、已验证结果、目标副本和状态。

- 同一报告文件只允许一个写入作业；Office 操作串行，不对同一 DOCX 并行写入。
- 缺一个结果或局部不支持格式，可以继续整理独立证据；完整交付标记保持未完成。
- Word 包损坏、源版本变化、输出归属不明等全局问题停止装配，不继续拼出“成功”文件。
- 一批变更优先在同一暂存副本完成，最终登记一个成功工作版本，避免每插一张图都制造用户可见的完整版本。
- 中断恢复先核对已落盘成果与登记事实；不能把“不确定是否写完”当成可以覆盖重跑。
- 页面关闭后长任务状态可恢复；下载失败只重试下载，不重复调用 Office。
- 同输入、同计划重试可以复用已完成输出。加密封套或 Office 元数据可能变化，不能仅用最终文件字节不同认定业务结果不同。

这属于报告副本装配，不是恢复此前已经取消的“项目文件夹逐文件继续更新”产品方案。

## 7. 补齐各类业务结果的具体范围

### 7.1 LLCR 与 CR

保留已经实现的局部更新保真和绝对量/ΔR兼容保护。旧 LLCR 模型的 `initial/delta` 仍是兼容计算标签，不能当作通用试验阶段枚举。

当用例要求多次试后绝对电阻时，在新契约中独立表达 chronology 与 quantity，再适配旧记录。支持准确的源单元格、实际测量电流、单位换算、扣除量和确认限值。公式缓存缺失不能当零，也不能用计算 ΔR 填补缺失的绝对值。

### 7.2 温升

复用当前成熟 Tools 的数据选择、样品分组、排除行、稳定阶段、拟合和图表。必须交接有效系数、零/非零截距和人工采用说明；Report 不悄悄重新拟合。

报告分别表达实测电流下的 Max、Avg of Max，以及指定电流下的回归结果。读取 032B 等关联 DOCX 时，先支持明确的温升表/原生曲线区域和人工确认；不要做一个任意报告万能解析器。

有关联报告原生图表时，应保留获准采用的表、曲线和说明；只有确有原始测量与计算依据才重建曲线，不能从像素图估计数据冒充原始测量。

### 7.3 机械力

复用现有文件夹 Summary。Report 直接读取其确认过的样品、颜色、部位、仪器记录与结果表，保留原始有符号值和明确的幅值展示规则。

保持峰值、定载保持、保持时间和接受条件分开。合并统计或按部位分组由本项目定义；不能固定为六条数据或三对样品。

附录标题根据实际结果类型生成，复核单位、颜色范围及样品合并；不沿用旧模板的 Orange/Mating 标签。原始曲线始终保留在审核 Summary，是否进入正式报告按报告需要决定，不默认全部插入。

### 7.4 IR 与 DWV

先支持现有受控记录表和代表性的真实历史格式，新增实测读取与报告投影，不再只生成空表。

必要字段包括测点对、样品、试验阶段、测试电压、持续时间、IR 数值/界限、DWV 击穿与漏电结果、单位及源位置。

`>1000 MΩ` 是区间约束，不是精确 1000；空白不是 0 或 Pass；nA/mA、MΩ/GΩ 必须显式换算；没有可比较的要求时不给出自动通过建议。

### 7.5 定性、外观、委外及跨项目沿用

不为每种试验建立一个按钮。提供结构化观察结果与证据范围，复用同一报告更新入口。

记录“观察事实”“普通判定”“例外接受理由”。照片可证明特定观察，不自动证明全部测试通过。Group 完成勾选只是进度，不替代每个结果的依据。

跨项目引用至少保存来源报告版本、来源项目、采用的试验/样品/材料范围、适用性理由及确认。获准引用的外部编号应进入允许引用清单；客户检查不能一方面要求追溯、一方面把所有非本项目 DL 都当残留错误。

若委外报告存在不利观察，系统展示冲突并保留本项目接受决定；不自动隐藏不利证据，不将历史特殊接受理由推广。

## 8. 底稿、图片及客户版设计

### 底稿分三类，不混用

1. **继续本项目原稿**：保留已有人工内容和有效结果，只更新明确选定区域。
2. **跨项目版式参考**：只继承结构与固定句式；建立全部项目事实、结果、附录、照片的替换/采用清单。
3. **标准空白模板**：沿用现有初始化行为，不把它伪装成已有结果的完整报告。

跨项目旧数据可在参考预览中看到，但不能在新项目审阅稿中不加区分地冒充本项目结果。尚未确认的旧业务区域不计入完成，生成策略应清空可安全识别的旧结果，或明确拒绝将该不明区域作为可交付内容。未知复杂区域继续人工处理，不能依靠一个“我已检查”勾选绕过明确的残留错误。

模板适配只先支持已使用的 E-3707/E-4515 和经验证的 Cable/Soft Busbar 结构。模板“配置”记录定位与布局，不携带旧项目数值、限值、Pass、日期或设备。

### 照片匹配

- 批量展示旧槽位、新照片候选和组别/步骤/样品/前后状态。
- 文件名、目录和图像相似度可以建议，不能作为唯一业务身份依据。
- 已确认的映射随源版本保存；重复进入不再逐张确认同一件事。
- 保留比例、裁剪、箭头、浮动锚点和共用图注；不支持的组合图明确提示。
- 图号按实际可见阅读顺序生成；排除 Logo、箭头、删除修订中的旧图及不编号温升曲线。
- 检查重复使用、遗漏、错组和旧项目照片残留，但允许有依据的同图引用。
- 原图对比不等于最终排版预览，仍需 Word 渲染。

### 客户版

让客户副本明确派生自同一份选定内部工作版本，不重新走另一个“最新文件”判断。

复用现有材料分类和深度包检查。当前代码已区分已知塑料与金属/陶瓷/未知 Housing，不需要重复修复“一律写树脂”的旧问题。

扩展的重点是：保留客户需要的完整结果和温升证据；按允许引用规则处理关联报告；检查批注、修订、属性、嵌入数据、外部链接、未引用旧图片及不可读对象。能证明未变化的审核记录可复用，未知对象不能静默判干净。

## 9. 分批实施计划

以下按收益、风险和依赖排序。每一批都有独立可用成果，不要求一次性完成全部后才交付。

### 第 1 批：统一报告工作版本及页面主路径

**收益最高；风险低到中，取决于是否涉及保存路径。**

范围：统一展示当前工作副本与正式现行报告；所有操作明确指向所选工作版本；保留旧初始化和更新能力，但防止误把重新初始化当成继续编辑。先不自动发布，不删除旧记录，不迁移真实文件。

缺少项目身份或确认 Matrix 时，清楚区分“可先整理资料”与“尚不能完成结果绑定”，链接到已有范围确认流程；不新增一套影子 Matrix。

主要落点：现有 ReportWorkspace、ReportAuthoringPanel、report authoring service、draft source resolver。必要时增加一个明确选定工作版本的引用，不建立第二个版本库。

验收：完善过的副本能继续更新；刷新和重开仍知道当前对象；客户副本来源一致；旧正式报告字节不变；只有用户明确选择重建才回到标准初稿。

### 第 2 批：Tools 到 Report 的结果直通

**高收益、中风险；温升计算不重写。**

范围：定义精简结果包，先连接机械 Summary 和温升。保留独立 Tools、现有文件导出和人工 Summary 兼容。Report 采用已有确认，只补 Group/Step 或真实冲突。

验收：同一结果无需重新选列、重填样品；温升有效系数不变；机械原始负号与展示幅值可追溯；人工改 Summary 后识别受影响部分；第二台电脑导入后能核验来源，不依赖第一台浏览器缓存。

### 第 3 批：资料盘点、覆盖清单和批量装配

**高收益、中风险；先覆盖已有结果类别。**

范围：受控项目目录盘点、来源角色与冲突；报告所需证据覆盖清单；事实/结果/附录的统一变更预览；批量应用；一次形成新工作版本。照片批量使用已有 assignments 能力，先解决已明确映射的槽位。

验收：多个已确认结果一次生成；无目标重叠或表序号漂移；未决项不伪装成功；源变化只使相关项过期；失败不改变原稿和当前成功版本；重复请求不产生重复业务成果。

### 第 4 批：补齐 032 场景的结果与沿用语义

**必要的业务完善，中到高风险。**

范围：IR/DWV 实测、定性矩阵、委外/关联结果引用、规格版本/日期角色；032B 温升表与曲线采用；必要的多阶段 LLCR/CR 适配。按类型渐进完成，不用一次替换所有结果模型。

验收：本方案第 2 节的冲突场景都有明确处理；缺值不转零，曲线数不足不补造；没有授权不沿用跨项目 Pass；接受理由有项目范围；数值、正文条件与附录语义一致。

### 第 5 批：批准稿覆盖检查、照片批量建议和 Word 视觉预览

**高收益、中到高风险，以副本验收。**

范围：模板语义区域与必替换字段；批量照片候选及一次确认；自动图号/引用检查；Word 渲染、受影响页查看与整份完整性检查。原稿固定内容与非目标区域保持。

验收：错误规格日期、Orange/Mating 表头残留能够发现；EXIF、共享图片、多图共用图注、浮动箭头和跨页表格有代表性检查；不固定报告页数，不靠缩字和全篇重排获得“通过”。

### 第 6 批：内部与客户交付闭环及发行环境验收

**需要谨慎的文件/版本操作，但不需要新的审批体系。**

范围：完整性与保密检查收口；选定审核成果通过明确动作进入现有安全保存/History 链；配对输出记录同一依据版本；复用现有后台任务与诊断；发行包和异机验收。

验收：输入或人工修改变化后阻止旧审核结果被冒用；文件占用和中断可诊断恢复；无 Word/Excel 时按功能给出准确提示；下载失败不重生成；未经授权不覆盖真实文件、不自动正式发行。

### 可选后续：辅助理解不规则资料

规则和已支持格式跑通后，再评估 OCR/模型辅助的收益。用途限定为识别资料、提出映射、定位矛盾和生成可核对的候选文本。

模型输出不直接成为测量、判定或发布授权。每个候选必须指向源页/单元格/图片；来源文档中的文字也不作为可执行指令。若采用云端模型，必须另行确定资料是否允许上传及运行环境；当前离线工具能力不能依赖用户个人 Codex 技能目录。

## 11. 验收方案

### 11.1 建立两类隔离基线

- **受控功能样本**：短小合成 Word/Excel/PDF，覆盖单位、计算、保护、兼容、冲突和失败恢复。
- **代表性项目副本**：032 全资料副本，另加至少一份不同结构的 Cable 项目，用于完整页面流程、真实 Office 与布局验收。

真实原稿、模板、项目资料只读，使用隔离数据库和工作目录；源文件前后 SHA 核对。用于版本库的夹具应脱敏；真实保密资料不直接提交 Git。

### 11.2 核心回归场景

| 编号 | 场景 | 必须得到的结果 |
|---|---|---|
| R01 | 021 参考稿用于 032 | 版式保留，旧项目事实与 Pass 不自动沿用 |
| R02 | Rev.2 的修订日期与授权日期不同 | 采用修订记录来源，日期角色明确 |
| R03 | Orange/Black 混合数据，旧标题 Orange | 标题覆盖真实颜色范围或提示冲突 |
| R04 | 保持力填入旧 Mating 附录 | 使用正确测量语义，不只改数值 |
| R05 | LLCR Initial/Final 标签冲突 | 记录确认依据；绝对量与 ΔR 不互换 |
| R06 | 温升已确认系数、排除行、样品分组 | Report 与 Tools 一致，不二次偷偷重算 |
| R07 | 实测 501 A 与 500 A 回归 | 分别标注和计算，不当同一结果 |
| R08 | 负拔出力、峰值、6秒保持同时存在 | 原值保留，展示规则明确，统计不混合 |
| R09 | 032 定性矩阵与原始曲线数不同 | 保存人工决定，不虚构逐曲线映射 |
| R10 | IR 的超量程/下限、DWV空白 | 保留比较符；空白不转 Pass |
| R11 | 委外不利观察但有本项目接受理由 | 完整留存依据，仅在授权范围采用 |
| R12 | 关联报告/邮件允许结果沿用 | 来源、版本和范围可追溯；不泛化到其他项目 |
| R13 | 源文件被替换、用户改了 Summary | 只使依赖内容需重新核对，不重复全部录入 |
| R14 | 原图旋转、共享媒体、箭头和组合图 | 只改目标槽位，无失真或误改其他图片 |
| R15 | 部分证据缺失 | 允许独立准备；不显示完整交付，不复制历史结果补空 |
| R16 | 客户版有嵌入表/修订/旧图/外链 | 能检测或要求准确范围复核；不错误宣称干净 |
| R17 | 新工作副本与旧正式报告并存 | 每个操作指向明确版本，不能静默回到旧稿 |
| R18 | 重启、断线、文件占用、重复点击 | 可恢复、可解释、不覆盖用户修改、不重复生成 |
| R19 | 第二台电脑与发行包 | 来源和确认可携带，路径不依赖开发机；Office缺失提示准确 |

### 11.3 分层测试而非堆积流程测试

- 纯函数：单位、量纲、阶段、统计和边界值；只对真正具有数学不变量的计算补属性测试。

- UI：使用公开页面行为验证选择、疑点解决、批量应用、刷新恢复、错误定位和下载。
- Office：隔离 Word/Excel 真实执行，重开输出、校验公式/曲线/原始区，Word 逐页查看。

## 12. 效率与可维护性要求

正常主流程争取做到：一次选择资料、一次集中处理必要疑点、一次生成审阅稿、一次交付审阅。首次模板配置和真实业务冲突允许额外操作，但不应每个项目重复。

使用现有日志记录盘点、解析、确认等待、装配、Office、渲染和下载耗时；对比优化前后：人工输入数、重复映射数、源文件重复读取量、完整副本生成次数、失败重跑范围。不凭代码行数或主观感觉宣称提速，不新增遥测数据库。

保留必要保护，减少无效门槛：

- 工程实现、定向测试和审查可在授权批次内连续完成，不新增 Planner/Reviewer 产品流程。
- 已确认、依赖未变的事实不重复提问；新的实质冲突一次集中呈现。
- 只影响局部的缺资料不阻塞独立准备；安全和身份问题仍停止相关写入。
- 高风险的是错误业务含义和文件覆盖，不是多一个普通控件；验证投入应跟随风险。

## 13. 风险与范围控制

| 风险 | 控制措施 |
|---|---|
| 合并报告链时覆盖现行稿 | 先统一工作对象，正式版本保持独立；最终显式采用，复用发布保护 |
| 误把整理/候选当业务权威 | 结果、要求、人工决定分开；候选不能自动确认 Matrix 或判 Pass |
| 人工修改后旧metadata继续生效 | 结果区域与源指纹验证，明确新版本，不自动覆盖用户修订 |
| 复杂Word结构破坏 | 先支持现有批准结构，未知槽位提示；局部修改与渲染验收 |
| 不规则PDF/扫描件误识别 | 支持边界显式，人工确认来源；OCR/模型仅候选 |
| 客户报告泄密或删掉必要结果 | 深度包检查与交付完整性并行验证，不能只做关键词脱敏 |
| 长路径、UNC、Office差异 | 复用短暂存与保护读取；覆盖发行包、异机、文件锁和中断 |
| 活动开发改变资料入口 | 先核对当前 Materials/Tools 任务合入结果，再冻结对应接口 |

不在本项目顺带实施：完整 LIMS、全仓架构重写、统一所有 API 类型、全部历史数据迁移、通用 OCR/AI 平台、自动正式发行、批量清理原文件或自动修改公盘模板。

## 14. 文档与实现的偏差

发现的少量文档滞后应在相关批次同步修正，不另开大型规则治理：

- `PROJECT_CONTEXT.md` 仍以两张报告卡片概括界面，没有完整反映已挂载的 authoring 区域。
- 该文件部分 Housing 脱敏描述仍比当前代码宽；代码已识别塑料、保留金属/陶瓷/未知材料。
- Tools 机械入口的部分文档仍写多文件选择，当前正常入口已支持文件夹。
- `PRODUCT.md`、`DESIGN.md`/`DESIGN.json` 中还有不暴露 Report/Matrix 的早期未来态措辞，与实际产品不符。

这些不能成为禁止现有功能的依据。需要更新本批涉及的准确说明，不删除全部历史文档或重新设计治理流程。
