# 已有结果／附录的页面定位选择

日期：2026-11-08。开发、审查、回归及隔离页面验证完成；本地集成事实见主看板／Git。等待用户验收关闭，不推送。发行包及异机验收未实施。

## 本次解决的问题

原代码已存在结果行与附录选择控件；此前称页面完全不能选择并不准确。实际缺口是已有附录时仍默认自动分配新附录，控件不显眼；预览写入新 revision 后清空选择区，没有从持久预览恢复修改的入口。

本次只完善现有前端及类型，不改后端生成、计算、来源／Matrix 权威、发布与 History 机制，不新增流程框架。

- 有已有附录时默认明确选择，列出标题、表头与位置；不自动选第一张或按标题猜测业务归属。
- 预览明确区分 `Update existing` 和 `Add new`，保留旧／新结果及目标位置的对照。
- 已保存／被阻止的预览提供 `Edit result and appendix locations`；重新读取当前候选，按精确表／行坐标恢复，不依赖列表顺序。
- 恢复时保留其他原选项；旧候选消失不改成新增，也不换成另一个候选。编辑即撤销确认，必须重新预览。
- 不把缺失的旧 LLCR 数据集静默换成新数据集；用户可明确将该项留待后续处理，独立结果可继续选择。
- 实际页面发现自动定位请求保存为 `result_table:null / result_row:null`，已修正前端可空类型和恢复判断，避免将唯一匹配行误清空。

## 如何操作

1. Report → `Update report content` → `Inspect materials and coverage`，选择需要更新的结果。
2. 对已有附录选择 `Choose appendix destination`，核对 `Report result row` 和 `Appendix destination`。选择已有附录会填入其标识；只有明确选择新增才建立新附录。
3. `Preview selected updates` 核对旧／新内容与更新位置。已有预览可直接点 `Edit result and appendix locations` 修改。
4. 修改后重新预览并确认，`Generate one working copy` 只生成工作副本，不覆盖原稿、不正式发行。
