## 范围与入口

复用 Report Workspace 的 **Update report content**、来源资产、版本记录与一次批量装配。
未增加数据库迁移、发布入口或通用工作流。真实报告、模板、项目资料只读；验证只用隔离副本。

1. 检查当前工作副本，按 Purpose、样品、结果、附录等区域列出继承内容与冲突。
   确认映射仅证明所映射事实，不顺带确认同段旧数值或 Pass。区域确认绑定位置、内容 SHA、
   来源版本和 Matrix；确定冲突不能通过一个总勾选消除。修订日期和授权日期分开核对。
   机械结果标题按局部关联核对试验种类与样品颜色，不把任意 Orange/Mating 字样当错误。
2. 选择已有照片候选，对照旧/新图，填写样品、阶段与用途，一次保存映射。
   试验照片绑定 Group/Step；概览或布置照片可用非步骤范围。相同字节重复使用须说明理由；
   旧图注 Group 与选择不同须明确核对，软件不静默改写图注。
3. 现有批量准备可使用确认后的照片方案及图号预览，一次生成新工作副本。
   来源被替代、输出或槽位变化、Matrix 变化会拒绝旧方案，不自动换图。
4. 图号按可确定的正文顺序计算，支持共享图注与 `3&4`、`7~9` 等复合标签。
   仅替换数字跨度，保留文字、样式、图片、箭头和引用周围内容。删除修订图不参与排序；
   固定非照片图号保留。域引用、复杂浮动排序、无法分配的共享图注或不连续范围明确待核。
5. 为当前精确工作副本生成 Word PDF。保留不可变 PDF 与输出 SHA，重开/下载不重新渲染。
   由实际 PDF 文本定位受影响页；无法定位时诚实提示整篇检查，不用段落索引猜页码。
   可一次记录整篇已检查，仍保留完整页范围与 PDF SHA；视觉确认不等于内容正确或正式发行。

## 实现边界

- `ReportDocumentReview` 负责版本绑定的覆盖与确认；Office inspector 负责 OOXML 区域、
  图注与精确局部编号。原有业务来源/结果验证保持权威，不信任上传的结果标签本身。
- `ReportPhotoPlan` 保存一次人工决策，再交给现有 assembly。批量 overlap、指纹、
  重放和发布保护仍生效；不会另建单独的文件写入通道。
- Word gateway 使用新建自动化实例、私有不保存的空白窗口交叉核验 PID，然后才允许
  超时控制持有该实例句柄。禁用宏、打开/打印外链和打印域更新，只读打开隔离工作副本。
  不枚举杀死所有 Word，不关闭用户已有文档。无法证明归属的进程不终止，错误明确提示。
- PDF 下载经项目/output 记录与资产校验，不能传任意路径；无 Word、渲染超时、旧版本或
  源变化均返回错误，不假装预览成功。现有 JSON revision 保存元数据，无新增数据库 schema。

## 限制与后续

不是通用语言理解器，也不是自动批准稿。无法归属的旧段落、来源不明确的日期、复杂 Word
域/浮动排版与特殊接受理由保持待核；不得从历史 Pass 推导当前 Pass。文档内容确认、
照片映射、视觉审核和正式发行是不同事实。首次 Word 渲染仍依赖安装的 Office/字体；
缓存仅对同一精确输出有效。第6批交付检查/受控保存与新结果类型均未扩大实施。

事实映射保留精确段落定位，而不是通用文档锚点迁移。其它更新造成段落位置变化时，需要
重新选择目标并确认映射；位置处未发现值不代表业务数值本身错误，软件不会猜测新位置。
