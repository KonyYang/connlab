# ConnLab 统一项目库与旧项目接管：目标方案

创建日期：2026-10-26；规则修订：2026-10-27。状态：用户已恢复 Goal A；TASK_UNIFIED_PROJECT_LIBRARY_20261027 在隔离环境执行。真实迁移 Goal B 未授权。

## 1. 业务目标

把其他电脑、人工目录、旧软件版本和本机不同 ConnLab 环境中的真实项目纳入统一管理。
首次支持数百个项目的集中接收，之后偶尔补充；用户能搜索、浏览原资料，并在确认关键资料后继续测试。
统一正式项目文件和正式业务数据的位置，程序更新不再生成另一套正式业务数据。
开发、自动测试和迁移演练使用隔离副本，不与正式运行实例共享可写业务库或正式项目输出位置。

本目标替代此前“只登记原位置”的单一设计。原位置登记仍可作为可选用途；集中接管是本次重点。

### 1.1 已确认的文件夹工作规则

1. **LTR 不变，标题可改。** 完整 LTR（包含已登记后缀）是用户查找和核对项目的主要业务依据；目录标题、显示名及绝对路径不是项目身份。修改 `DL-2026-09-032` 后面的标题不创建新项目、不重新发号，也不自动改写 LTR 登记、申请单和已有报告。内部保留稳定项目 ID，以区分副本、历史和同编号冲突，不要求用户手工维护它；不能以 LTR 作为覆盖或删除数据库记录的唯一键。
2. **允许日常增删改。** 用户可以通过资源管理器新增、复制、编辑、删除普通文件和子目录，也可以新增自定义目录。刷新或再次访问时应反映变化；这些变化不改变项目身份，不因整个目录内容哈希变化就拒绝接管。删除文件后只标记相关引用缺失，不自动补回、恢复或重建空白文件。
3. **模板是起点，缺失按用途处理。** 已核对模板 `D:/Source/Template/DL-XXXX-YY-ZZZ project/`：外层包含带 LTR 标题的内层业务目录和同级 `Source Book`；业务目录包含 E-mail、Photos、Submitted Material、Test results/Final Examination。接收时识别完整边界，不遗漏 Source Book；允许旧目录结构不同，不能要求先整理成模板才接收。需要某目录的具体操作可以提示补建，补建须为明确动作，不能覆盖已有文件或重建整个项目。
4. **改名、移动后可恢复关联。** ConnLab 内修改标题时同步受影响的路径引用；在资源管理器直接改名后，依据稳定身份与完整 LTR 核对候选，唯一且可验证时恢复关联，多候选时让用户选择。跨磁盘或电脑不依赖原绝对路径或原磁盘的文件系统身份，提供定位/接管入口；身份清单丢失时可人工重新核对，不自动把同编号目录认作原项目。
5. **整个项目可跨电脑接管。** 在项目根目录的软件管理区域（优先复用 `.connlab`）携带稳定身份、带版本的项目数据快照及所需关联资料。移动/复制整个项目后，另一台兼容 ConnLab 不依赖原电脑数据库即可检查、恢复并继续工作。现有身份清单不等于完整数据快照；普通文件操作无需逐份导入，软件管理区通过软件维护，受损时给出恢复指引。
6. **快照有来源和新鲜度，副本不自动合并。** 当前数据库是本机结构化工作的状态来源；随行快照是显式版本化的导出/恢复载体，不形成另一条静默双向写入通道。明确显示快照时间、项目版本和是否覆盖当前进度，提供刷新/准备带走动作；旧快照不能冒充最新状态。复制后识别为同一项目的候选副本，已有记录、两地修改或不同版本需对比确认，不按最新修改时间或相同 LTR 自动覆盖/合并。
7. **外部文件修改与正式确认分开。** 修改 Excel/Word 不自动改变已确认 Matrix、测量记录或测试完成状态；软件提示关联资料已变化，只影响依赖该资料的操作。缺失资料不妨碍保存、查找、浏览和继续补齐，历史测量结果与报告不被新空白表覆盖。


### 1.2 按原有文件夹习惯使用

| 用户操作 | 方案要求 |
| --- | --- |
| 修改项目标题 | 例如把 `DL-2026-09-032 CPI-450 with Soft busbar Qualification Test (9.7)` 的标题改成新名称；完整 LTR 和内部项目身份保持不变，仍能按 LTR 或新标题找到原项目。软件内修改及资源管理器改名都纳入验收。 |
| 日常整理资料 | 在项目内直接复制、增加、修改、删除普通文件和子目录；无需每次重新导入。刷新后显示实际内容；引用缺失只提示受影响的资料或操作，不清空已有测试数据。`.connlab` 等软件管理区由软件维护，界面应说明其用途。 |
| 从其他电脑继续测试 | 在来源 ConnLab 中执行“准备带走/更新项目数据”，核对快照是否包含最新进度；复制整个项目根目录；在目标 ConnLab 中选择项目、检查数据范围和冲突，明确确认接管，再进入现有工作台继续测试。 |
| 接收人工目录或旧版本项目 | 即使没有随行快照，也可先接收原文件并浏览、补齐资料。若结构化测试数据仅存在于旧库，必须显式读取兼容的旧库副本或另行导出；不能从目录名推断、虚构数据，也不能把此类项目宣称为测试数据已完整恢复。 |

“准备带走”应检查软件已持久化的最新进度，并提示未保存内容；更新失败时保留上一次完整快照及明确失败状态。目标电脑不继承来源电脑的凭据、公共盘写入许可或机器专属设置。

## 3. 两个独立完成目标

目标 A：实现并在隔离环境完整验收统一项目库、复制接收、数据库迁移演练、文件夹自由操作后的关联恢复，以及整个项目跨电脑携带测试数据并继续工作的能力；交付真实切换所需的清单、工具与恢复方案。真实环境尚未迁移不影响 A 的完成，但必须明确标记。

目标 B：用户审查 A 的迁移清单后，明确指定源库、源目录、目标根目录、冲突决策和允许的切换动作，再执行正式迁移。B 不包含在 A 的授权中。源资料删除、旧库淘汰及推送发布均不随迁移自动获准。

## 4. 目标 A 的执行权限与约束

- 可以只读盘点候选真实业务目录和数据库，限制在相关项目范围，不扫描 D 盘所有私人目录。
- 可以修改本任务代码、测试、文档；使用隔离数据库、缓存、日志、构建目录和项目样本副本进行验证。
- 可以在临时/隔离空间制作必要的数据副本。数据库必须获得一致快照，识别 WAL 等伴随状态；不能把运行中的 SQLite 主文件直接复制后当成完整备份。
- 不修改、迁移、重命名、删除或覆盖真实项目资料、真实数据库、正式配置和权威 LTR；不触发真实正式输出。
- 在隔离 worktree/checkout 中实现，避免开发服务器自动重载新增代码并初始化真实库；全部启动参数显式绑定隔离路径。不得启动连接真实默认路径的应用作测试。
- 不停止用户现有正式进程，不改变其数据绑定；需要一致性维护窗口时记录缺口，先完成不依赖它的工作。
- 不推送、不发布、不自动关闭其他任务；最终仓库 Close 仍由用户明确下达。
- 使用现有仓库工作流，高风险部分使用独立 Planner、Developer、Reviewer、QA、Integrator 上下文；如缺少条件，如实记录。
- 主任务槽占用时可继续只读盘点和设计；不得擅自挤入第二主任务、将此功能降为 micro，或关闭占槽任务。

## 5. 里程碑与交付

### M0：真实现状与迁移边界

盘点两套环境的项目、数据库版本、关联资料、项目根目录、模板、附件及配置引用；识别真实项目、测试样本、备份和补充资料。
比较项目身份、编号和内容证据，不能仅凭数据库大小、修改时间、同名目录或旧 ID 选择主库或合并。
追踪现有目录、身份清单、数据库记录和外部权威的关系；列出能复用的现有能力，避免重复实现。
逐类盘点需要随项目带走的结构化数据和文件：项目事实、已有编号关联、样品、Matrix 草稿/已确认版本、当前代码实际持久化的测试计划/进度/测量数据、报告、来源与历史。区分结构化记录和仅存在于原文件的测量数据，不虚构当前尚未持久化的执行数据。确定软件管理区的位置、快照版本契约、项目边界和外部依赖。

交付：来源清单、项目/资料关系表、库间重叠与差异、目标结构建议、支持/不支持的数据范围，以及精确实现路径和验收矩阵。
无法确定的业务归属保留待确认；不把猜测写成正式事实。

### M1：统一存储与环境边界

实现可配置的正式数据根目录，区分业务数据、项目、配置、日志/缓存和备份；适配现有外部资源、权威 LTR 与模板配置，避免生造第二套路径权威。
开发和发行程序可通过受控配置定位指定资料库；开发测试默认保持隔离。不同软件版本不得无检查地轮流升级或同时写入同一正式库。
数据根选择、版本兼容、实例写入边界及迁移后的旧路径引用均需有明确检查。
把稳定项目身份与可变标题、目录位置分开；复用现有身份和重绑定能力，普通文件增删改不触发项目身份失效。按需刷新/校验即可，不要求通过常驻全盘监控才能工作。

验收：在沙箱中模拟开发与发行入口，重启和替换程序后仍定位同一指定业务库；测试入口始终指向独立副本，错误环境绑定有明确提示。软件内与资源管理器改标题后仍关联原项目；普通文件新增、编辑、删除和自定义子目录不使项目身份失效；删除被引用文件只标记对应缺失。标题变化不改写已有业务文档。

### M2：批量复制接收

Tools 入口：选择来源 → 自动识别并检查 → 核对项目、目标及冲突 → 确认接收 → 结果与待办。
支持整项目、包含多个项目的父目录及零散文件；零散文件需明确加入已有项目或待整理项目。
允许纠正父子目录的项目边界。无冲突项目默认选中，少量待确认项不阻塞其余接收。
保留模板的内层业务目录与同级 Source Book 的完整范围；兼容其他历史布局，不为满足模板而自动移动、删除、重命名内部资料。
默认复制到受控临时目录，核对清单和文件内容后提交到最终位置并登记；保留来源信息及内部目录结构。
禁止覆盖同名目标；相同内容可识别重复，不同内容保留版本及来源。项目身份与目录显示名分离。
具备批次记录、中断恢复、重试幂等、源变化检测、空间不足/锁定文件/长路径处理；不跟随不安全的重定向越出确认边界。

验收：至少 300 个不同形态的隔离项目，覆盖同名异项目、同项目多来源、同名异内容、父子边界、零散文件、失败重试和进程中断；原样本保持不变，失败项不被登记为完整成功。

### M3：跨环境业务数据迁移演练

以 M0 的真实数据关系为准实现显式迁移策略，保留项目与附件、已确认 Matrix、已有记录、报告、历史和相关引用。
不得直接拼接数据库或以目标记录覆盖来源记录。同 ID 不同内容、不同 ID 同业务项目和外部路径冲突需要明确决策。
旧版本无法无损转换的数据保留原始快照、可读证据和阻塞项；不能悄悄丢弃，也不能声称全部迁移。
模拟迁移生成目标库及重定位后的附件副本，不写源库；可重复校验和恢复。真实主库选择由审查结果决定。

实现项目级可携带数据快照的生成、刷新、检查与恢复，不直接复制整台电脑的全局数据库作为单项目携带方案。快照记录格式版本、项目身份、数据修订、生成时间、导出范围、所需文件与完整性信息，恢复时验证兼容性和缺失项。
数据库中的现有结构化测试数据及其关系应随项目恢复；仅保存在 Word/Excel 中的历史测量值连同原文件保留，不未经确认转换为正式结构化结果。公共 LTR、模板及外部引用保留来源与配置待办，不把其他项目的数据、凭据或机器专属设置打包进项目。
恢复时重建目标电脑的本地路径关系；快照更新采用完整提交与失败恢复，不将半写快照视为有效。目标已存在同项目时比较身份与修订，重放幂等；分叉、快照过旧、文件在快照后已变更、格式不兼容和损坏均给出明确状态，禁止静默覆盖。

验收：源记录到目标记录有可追踪映射；关键记录数、关系、文件内容和状态逐项核对，二次运行不重复；已存在的测量结果和已确认权威不丢失。未覆盖的持久化类型必须列明，不以小部分导入代替完整迁移交付。
使用独立的模拟电脑 A/B 数据根和数据库完成跨电脑验收：A 准备可携带快照 → 复制整个项目到不同路径的 B → 原 A 数据库不可访问条件下接管 → 核对全部已声明携带的数据、文件、历史和关系 → 继续编辑测试草稿并保留前后版本。不能让 B 偷读 A 的数据库或沿用原电脑绝对路径来通过测试；平台差异另作真实机器复验清单，不把同机模拟声称为真实双机实测。

### M4：接管并继续测试

用户可选择仅保存查阅或继续测试。后者核对项目身份/已有编号、样品、测试计划与既有完成情况后进入现有工作台。
优先复用现有草稿和确认规则；“待接管”具体如何表达由真实模型决定，不预先强制增加生命周期枚举。
资料缺失只阻止依赖它的动作，允许先保存、查找、浏览和补齐。推测值只作为待确认建议。
旧文件、测量记录与报告保持可追踪；不把存在文件等同测试完成，不自动重新发号，不把历史结果写成新的空白表。
列表提供搜索、直接打开、本次接收筛选、必要的显示名称/备注与可理解的待办，英文界面沿用现有风格。
展示项目随行数据是否已更新、快照时间及缺失依赖；带走/接管动作使用可理解的入口。被删除或修改的资料只使相关动作提示复核，不阻断与该资料无关的日常浏览或编辑。

验收：完整项目、资料缺失项目、跨版本重复项目各完成一条隔离接管路径；既有项目按迁移后确认权威继续，未确认内容不驱动正式输出；新草稿/输出不覆盖旧结果。

## 6. 验证和 Goal A 完成条件

1. M0–M4 全部完成，逐项给出通过、未通过或明确阻塞；不能以文档或演示页面代替可运行能力。
2. TDD 保留有意义的 RED/GREEN；独立审查无未解决的阻断问题。
3. 在最终被审查代码上运行与风险匹配的 Python、前端测试、类型检查、构建和隔离 UI 复验；Vitest 与 Vite 构建顺序执行。
4. 包含至少 300 项批量接收、重试不重复、恢复、冲突不覆盖、源变化、跨库关系、资料缺失及继续测试验证；覆盖完整模板边界和不同历史布局。
5. 样本原件和源库保护有证据；无法证明的项必须明确标记。既有测试失败要单独报告和验证基线，不能称完整测试通过。
