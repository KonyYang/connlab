# Import Projects 最小目标方案

日期：2026-10-29。当前用户目标与真实代码优先；本方案是现有导入任务的继续。

## 用户操作

1. 页面首先显示实际保存位置及 Change / Open Folder。普通开发和发行实例沿用 Settings 的 Project default save location；未配置时在当前页引导选择已有目录。保持数据库和数据目录不变。显式管理库保留原有绑定和路径约束。
2. Choose Project Folders 选择一个完整项目或装有多个项目的上级目录后自动检查。手动输入路径只作备用。清楚显示正在检查、错误原因、项目数量与重复/冲突，取消选择不删除文件。
3. 检查结果中直接列出可导入项目。普通文件和 ConnLab 快照在同一入口识别；含快照项目明确展示将恢复的数据、原件缺口与冲突处理。不得静默恢复、覆盖、合并或转移公共目录写入权限。
4. 明确的最终确认显示数量、保存位置与数据恢复范围。确认之前不创建项目副本或业务登记。成功后可查看项目、打开文件夹、继续导入。

## 最小实现边界

- 复用现有 Settings 项目目录登记、扫描、批量接收、快照恢复和冲突令牌；不创建另一套数据库，不搬迁数据库，不改变 LTR/标题/文件日常修改规则。
- 已配置显式管理库的实例继续沿用其根绑定；普通实例从当前数据库读取有效项目保存位置。目录必须存在、为绝对目录且无重定向；切换目录不会搬动已登记项目。
- 目录变更使旧导入/恢复计划失效，必须重新检查。计划及确认均核对目标目录；错误不能授权复制或恢复。
- 批量快照逐项目沿用已确认计划；归属保护核对该项目及同 LTR 的记录。其他 LTR 的登记不会误使后续计划失效，同 LTR 占用变化仍须重新检查。
- 已识别的完整项目默认保留整体边界；仅在需要处理边界时显示清楚的调整选项，保留源文件与 Source Book。
- UI 使用现有英文、组件与样式；手工路径和原地关联放入高级选项；不再要求用户选择普通导入或快照恢复这种技术路径。

## 验收

- 无显式 library_root 但已有 Settings 项目目录：可预检、确认、查找浏览，数据库路径和数据目录保持不变。
- 无保存位置：不显示误导性的默认目标；提供设置动作，未确认配置前禁止导入。无效/不可用/重定向路径不写入配置或项目文件。
- 单个与批量选择自动检查；取消选择、重新选择、慢请求返回、错误重试与页面返回不引入过期结果或重复提交。
- 普通项目与含快照项目均可由同一入口发现；重复、同 LTR 冲突、相互覆盖边界、快照缺口、恢复版本保护和显式最终确认保持有效。
- 确认前项目目录为空、登记数不变；确认后只在隔离目标中复制/恢复。改变目标后旧计划必须被拒绝。
- 用隔离数据库与现有样本复验；源目录名称、结构、内容、时间及哈希不变；原确认 Matrix、测量结果和历史版本保留。
- 前端相关测试、类型检查、构建、相关 Python 测试及隔离 UI 验收通过；审查最终 diff；仅本地提交与集成，不推送、不发布、不自动关闭任务。

## 主要风险

保存位置与管理库根绑定混淆、检查中的异步结果覆盖新选择、批量恢复中部分失败及重复提交、旧确认令牌跨目标复用。优先用公开 API 和用户可见行为回归保护这些边界，禁止通过放松原有冲突或完整性规则解决 UI 问题。
