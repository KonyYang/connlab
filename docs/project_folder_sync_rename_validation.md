## Correction and boundaries

- Preview, Auto sync and binding requests share the existing synchronous operation guard.
  A slow preview retains its confirmation; Auto sync cannot invalidate its owner.
- Selected workspace repository compositions resolve a missing description link through
  the existing relocation service. A raw repository/service is used inside recovery to
  avoid callback recursion. Ordinary repositories retain their existing read behavior.
- Automatic repair holds the canonical project writer lock and rejects unfinished
  generation, basic-folder, file-generation and report-save operations. Normal preview
  resolves before guarded writes; an already-held writer lock returns a review error.
- Only the same registered filesystem directory identity, unique complete-LTR child,
  matching manifest/project and registered workspace can be rebound. Custom descriptions
  remain unchanged. Legacy identity, ambiguous or replaced directories, changed LTR,
  redirects and offline paths do not grant association or overwrite authority.
- The existing keep-custom relocation journal, manifest locking and publish_relocation
  update verified file assets, folder records, material targets and output provenance.
  Only a matching same-project/same-workspace keep-custom interrupted operation can
  resume automatically. No business directory is moved or regenerated by lookup repair.
- A lookup may now repair trusted metadata in these compositions. Shared canonical-lock
  exclusion and existing lifecycle write rules still apply; reopening remains required
  where a closed project does not allow the existing relocation workflow.
